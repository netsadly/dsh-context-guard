# Context Guard：Harness 上下文保护与会话恢复插件

**MIT 开源实验版。** 已验证宿主：DeepSeek Harness **0.2.1-rc.5**；模型服务：本机 LM Studio。其他版本尚需验证。

## 作者与实现

**框架由作者 netsadly 设计，实际代码书写由 GPT Astra 完成。** 作者负责需求、框架方向和验收决策，GPT Astra 辅助完成代码实现、迭代与测试。这是独立社区插件，不代表 DeepSeek、LM Studio 或 OpenAI 的官方产品或背书。AI 参与实现不等于代码绝对正确，测试范围见 [验收报告](docs/VALIDATION.md)。

## 解决什么问题

本地模型长期运行任务后，对话、工具调用和大段工具输出会不断积累。输入超过 LM Studio 当前加载的上下文窗口时，Harness 可能无法继续生成；反复发送“继续”并不会腾出空间。有时界面提示“输出 token 上限”，实际原因却涉及输入容量、异常输出预算或压缩失败，不能仅凭提示判断。

本插件读取模型**实际加载的窗口**，结合本地分词、工具定义、输出预留和安全余量计算预算。接近阈值时，通过 Harness 原生压缩事务生成摘要，减少后续请求携带的历史。对于已经过长的会话，提供可断点续跑的手动恢复，避免所有分块挤在一次界面命令的时限内完成。

它不会扩大模型物理上下文、修改权重或增加显存，也不能修复所有输出截断。摘要有损，原始记录仍是事实核对依据。

## 功能

- 读取已加载模型的实际窗口，不拿宣传的最大窗口代替。
- 预算包含消息、工具、输出预留与安全余量，阻止超预算请求。
- 阈值触发自动压缩；保留有效输出上限，只修复过小的异常预算。
- 手动恢复每次最多新增两次模型请求，保存合格摘要与超限拆分位置。
- 重启后可续跑；检查点绑定输入、会话、模型、容量、配置和摘要提示，条件变化会隔离旧结果。
- 全部完成后才通过原生事务提交；部分完成、截断或取消不提交不完整替换。
- 原始事件保留；恢复命令不继续执行历史任务。

## 安装前须知

**验证缺口：没有全新的 Windows 环境。完整的 Harness 安装、启动、启用／停用及原生服务恢复流程，尚未在全新 Windows 系统上验证。** 现有电脑中的隔离依赖安装测试不能替代这项验收。

本版仅针对 **Harness 0.2.1-rc.5、本机 LM Studio、文本会话**。启用会停用全局原生 `compaction-basic`，影响不限于当前会话。其他提供方不会获得本插件的压缩保护，也不能假定仍有原生压缩兜底。切换提供方或使用多模态前，先停用本插件、空闲重启并确认原生服务恢复。图片、音频、文件块会被拒绝；升级宿主后需重新验证。

## 安装教程（Windows）

### 1. 准备环境

准备 Harness 0.2.1-rc.5、Node.js 22 或更新版本、LM Studio。在 LM Studio 加载文本模型并启动本地 API 服务，确认 Harness 的 `lmstudio` 提供方使用同一个准确模型标识。

默认端点是 `http://127.0.0.1:1234`。本版只支持回环 HTTP 地址，摘要专用传输尚未实现 API 密钥认证，不支持远程端点。无需向公网开放服务。

### 2. 获取源码

将插件单独放入可长期保留的目录：

```powershell
git clone https://github.com/netsadly/dsh-context-guard.git
Set-Location dsh-context-guard
```

也可从 GitHub 下载 ZIP 后解压。无需作者的其他项目、会话或模型文件。

### 3. 准备 SDK

插件使用 `@lmstudio/sdk` **1.5.0**。以下 A、B **只选一个**，并在同一个 PowerShell 窗口继续第 4 步。

**A：复用已安装的 1.5.0 SDK**（此前本机验收路线）。替换示例为真实入口；不要再执行 B：

```powershell
$sdkEntry = 'C:\SDK\node_modules\@lmstudio\sdk\dist\index.mjs'
```

**B：在插件目录新装 SDK**（需要 npm 网络；不等于已完成干净机器桌面验收）：

```powershell
npm ci --ignore-scripts --legacy-peer-deps
if ($LASTEXITCODE -ne 0) { throw 'SDK 安装失败，请停止并排查' }
$sdkEntry = Join-Path (Get-Location) 'node_modules\@lmstudio\sdk\dist\index.mjs'
```

`npm ci` 使用仓库锁文件固定依赖树；`--legacy-peer-deps` 让原生宿主依赖由现有 Harness 提供。`--ignore-scripts` 不运行依赖安装脚本。SDK 及宿主仍需验证版本和运行兼容性。

### 4. 生成安装目录

找到自己的 Harness 安装路径。以下路径仅是示例，必须替换：

```powershell
$hostModules = 'C:\Apps\DeepSeek Harness\resources\app.asar\dsh\node_modules'
# 保留第 3 步选择的 SDK 路径，不要重新赋值。
if (-not $sdkEntry -or -not (Test-Path -LiteralPath $sdkEntry -PathType Leaf)) { throw 'SDK 入口不存在，请检查第 3 步' }
node scripts/prepare-local.mjs $hostModules $sdkEntry
```

`app.asar` 是 Electron 归档，内部路径不一定能像普通文件夹一样浏览。脚本在创建或覆盖配置前检查 SDK 入口是可读文件，随后生成供 Harness/Electron 使用的绝对导入地址。它不校验 SDK 版本、依赖完整性或归档内的宿主模块；生成成功不代表插件已启动。不应指向不同版本的宿主。

生成目录为 `private/local-plugin`。它含本机路径，**只供本机安装，不上传 GitHub、不发给别人直接安装**。安装后不要移动或删除源码目录、生成目录和引用的 SDK。

### 5. 在 Harness 启用

打开 **插件 → 添加插件**，选择 `private/local-plugin` 并启用。安装包会停用原生 `compaction-basic` 项并插入 Context Guard 服务。会话空闲时退出并重开 Harness，检查插件组件处于运行状态。

没有出现命令时，检查是否启用、生成路径是否有效，再空闲重启。不要同时运行其他替代压缩服务的插件。

## 使用说明

### 查看预算

输入框左下角点 **＋ → context-guard**，选中命令标签后输入 `status` 并发送。直接粘贴 `/context-guard status` 可能被当成普通聊天文本交给模型，应使用命令标签。

| 返回字段 | 含义 |
| --- | --- |
| `capacity` | 模型实际加载容量 |
| `output` | 输出预留 |
| `available` | 扣除输出与安全余量后的输入预算 |
| `trigger` | 主动压缩触发阈值 |
| `estimatedInput` | 含保守余量的分词估计，不是提供方聊天模板的精确值 |

例如容量 30,208、输出预留 8,192、安全余量 2,048 时，输入预算为 19,968，80% 阈值为 15,974。不要强行套用到不同模型。

### 日常自动保护

启用后，支持的本地文本会话在模型请求前检查预算。接近阈值时尝试压缩；不安全或压缩失败时停止请求。自动压缩保留原来的有界流程，手动检查点机制不会自动接管日常压缩。

### 恢复过长会话

1. 停止任务，等待会话空闲，独立备份对应记录。保留原事件不等于自动创建了外部备份。
2. 点 **＋ → context-guard**，输入 `recover` 并发送。
3. **Recovery paused** 表示保存了部分进度，尚未完成；再次选择该命令发送 `recover`，不要发送普通聊天“继续”。
4. 重复直到出现 **Recovered … history items**，表示完整摘要已提交，历史任务没有自动执行。
5. 先发送“不调用工具，只回复测试通过”进行简单验收，再对照原记录核对关键约束和进度。

每次最多新增两次请求，摘要阶段最多 210 秒，尽量在宿主约 5 分钟的命令时限前结束。极慢的单次请求仍可能超时，已完成检查点留给下次使用。不能保证任意长度的记录都恢复成功。

### 检查点、备份、更新和停用

检查点位于 `%USERPROFILE%\.dsh\context-guard-checkpoints`，为**未加密的本地明文 JSON**，含私人摘要。本插件不会将这些文件上传 GitHub；宿主、操作系统、备份或同步软件的复制和上传行为不在插件保证范围内。校验和用于发现意外损坏，不是认证或防篡改机制；能改写文件及校验和的人仍可能伪造内容。暂不自动清理；Harness 空闲时删除对应检查点只会丢失恢复进度，不会删除原始会话。

会话通常位于 `%USERPROFILE%\.dsh\sessions` 下，文件名为 `session.v4.jsonl.zstd`。备份保留原文件并核对 SHA-256，不覆盖正在使用的记录，不提交个人备份到本仓库。

更新源码后重新运行生成脚本，再空闲重启 Harness。配置或输入变化会隔离旧检查点，可能重新计算。停用时在插件页禁用本插件并重启，确认原生压缩服务恢复；这不会撤销已完成的摘要事务或删除备份。

## 默认参数

| 参数 | 默认值 |
| --- | --- |
| 本地服务 | `http://127.0.0.1:1234` |
| 异常输出预算替代值 | 8,192 token |
| 单次摘要输出上限 | 2,048 token |
| 安全余量 | 2,048 token |
| 主动触发比例 | 可用输入预算的 80% |
| 自动压缩保留尾部目标 | 约 2,000 token |
| 安装包摘要树时限 | 600 秒；手动恢复最多 210 秒 |
| 每次手动新增请求 | 最多 2 次 |
| 逻辑摘要树调用上限 | 32 次，缓存节点也计入 |

配置模板为 `cordis.patch.yml`，修改后重新生成并重启。提高输出预留会减少输入空间。

## 限制与排错

- 只支持当前本地文本路由；图片、音频、文件内容会被拒绝，避免低估预算。切换其他提供方前应停用本插件。
- 依赖版本固定的 Harness 内部 API，更新宿主后需重新验证。
- 摘要为精简英文并尽量保留原始标识符，不改变日常对话语言。词数与字符数是提示目标，硬限制由 token、调用数和超时控制。
- `TOKENIZER_BUSY`：上次 SDK 分词 RPC 未结束，等待后重试；长期不结束则空闲重启，不会无限叠加请求。
- 容量读取失败：检查模型已加载、准确标识一致、本地服务可达。
- 检查点损坏：停止恢复，不使用损坏摘要。先保留目录供排查，空闲时将其移出检查点目录后重试。
- 摘要有损；这是上下文保护插件，不是保证所有事实永不遗漏的记忆系统。

## 已记录的恢复结果

[验收记录](docs/VALIDATION.md)记录了一次重启续跑成功：46 个历史项完成恢复，440 条原始事件保持不变，带余量的输入估算由 81,598 降至 9,724。随后短回复验收没有工具调用。这是特定版本和会话的历史验收记录，本次文档修改未重跑真实恢复；不表示历史任务已恢复执行、所有事实完整保留或任意崩溃会话都能恢复。
