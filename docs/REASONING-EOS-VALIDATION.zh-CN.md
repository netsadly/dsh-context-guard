# 思考空正文保护：验证范围

此补丁建立在 v0.2.0 之上，属于有界恢复，不是模型权重或推理引擎的 EOS 修复。

## 实际代码行为

- 配置的本地提供方返回正常 stop，但只有思考、没有非空正文或工具动作时，改记为明确失败。
- 原生 Harness 保存原始思考和用量为失败 attempt，不把思考冒充正文，不改写旧消息。
- 每个活跃轮次最多允许一次此类恢复；保留所选思考、模型、工具、采样和加载容量。
- 第二次此类失败后，发送前屏障阻止后续模型调用，即使外围宿主配置了始终重试。
- 正文、工具调用、取消和输出额度耗尽保留原有语义。已有摘要与停滞阶段答复走独立路径。

## 自动测试与审查

2026-11-21：88 项测试全部通过，0 跳过。包括 2 项真实本地模型摘要测试，以及实际 Harness agent loop、retry 插件与合成响应的 10 个组合场景。组合覆盖两种注册顺序、always/自定义 normal 策略、恢复成功、工具仅执行一次和取消。原生组件加合成模型流不等于真实模型答案质量验收。

Standards 审查发现外围重试可绕过原始 hook 上限；已增加独立发送屏障并通过复审。Spec 复审无阻断问题。

## 真实模型实验的限制

原失败上下文在真正生效的 Medium 模板下仍 4/4 次思考后 EOS 无正文；输入 token 变化确认模板确实改变。频率惩罚 0.3 的小样本也未稳定消除问题。实验后原模型加载配置完整恢复，未将这些候选参数作为已验证修复。

独立复杂任务 API 测试中，默认模板的代码题和约束优化题耗尽 4096 个输出 token 仍无正文；工具对账题算出正确金额，但违反严格 JSON 输出要求。真正生效的 Low 模板也未全部通过：代码正文出现但 JSON 双重转义使代码无法直接执行，优化题仍耗尽额度，对账题仍有格式问题。这些失败不能计入验收通过。

因此，测试通过只证明插件保护与兼容性；不证明任意复杂任务可正确完成，也不证明 LM Studio 自身界面的空正文问题已根治。更换推理引擎或模型的有效性需要单独对照验证。
