# v0.1.2：系统预设保留与分词并发修复

2026-11-16 · 实验性预发布 · DeepSeek Harness 0.2.1-rc.5 / 本机 LM Studio / 文本会话。

## 更新内容

- **阶段答复保留当前预设**：原先重复无进展保护进入阶段答复时，会重建消息而漏掉当前系统提示。现在按原顺序保留当前请求的全部system消息，包括已有角色、语言与语气要求，再附加收束说明。不从旧历史恢复过时预设，不改写输入和原始记录。
- **完整预算保护**：保留的系统提示全部计入最终输入预算；超限明确停止，不截断角色设定来腾空间。
- **分词并发有限等待**：正常重叠计数不再立即报TOKENIZER_BUSY；最多四个调用等待，实际RPC仍最多一个，排队与执行共用原有超时。等待取消不会发起RPC；已取消或超时而未结束的RPC继续保锁，防止请求积累。
- **回归覆盖**：增加系统提示顺序、旧预设隔离、输入不变、超预算拦截、连续原生压缩和分词排队/取消/超时测试。继承v0.1.1的摘要标题规范化修复，不回退旧版本功能。

## 升级方法

1. 等待Harness任务空闲，独立备份配置、已安装插件及重要会话，并验证备份可读。不要用旧会话备份覆盖新工作。
2. 将本Release源码解压到新的永久目录；或在干净源码副本执行：

```powershell
git fetch --tags origin
git switch --detach v0.1.2
```

3. 按[中文安装教程](../README.zh-CN.md)准备Node.js 22+、匹配的Harness宿主模块和`@lmstudio/sdk` 1.5.0。需要安装依赖时用`npm ci --ignore-scripts --legacy-peer-deps`；已有可用SDK可沿用。
4. 在新版源码目录重新生成本机插件包：

```powershell
node scripts/prepare-local.mjs '<Harness宿主node_modules路径>' '<SDK的dist/index.mjs路径>'
```

5. 在Harness插件界面把安装位置更新到新版生成的`private/local-plugin`，避免同时启用两份同名插件。保留自己的预算覆盖项、角色预设及模型配置，不用仓库模板覆盖它们。生成包包含本机依赖路径，不可转发给另一台机器。
6. 空闲时完全退出并重启Harness。无需改变模型、MTP、GPU或上下文大小。通过指令菜单执行`context-guard status`核对容量，再用现有预设新建会话执行一次真实工具任务；继续一个已有会话，确认阶段答复后工具可恢复。
7. 若之前已设置思考等级映射，继续沿用；本补丁不会自动安装、修改或加载模型定义。需要重载时参阅[思考等级加载注意事项](REASONING-LMSTUDIO.zh-CN.md)。

本机16K级验证使用输出2048、摘要2048、安全余量2048、阈值0.9及保留尾部2000，仓库默认预算没有更改。应按实际加载窗口确认预算，不能直接照搬更大的输出上限。

回退：任务空闲并退出Harness，恢复上一版插件安装位置或本地入口，重启核对。保留新旧运行包、配置及全部会话；停用插件不等于撤销已提交摘要。

## 已知限制

- 本修复避免插件在阶段答复中漏掉系统提示，不保证任何本地模型永远遵守所有角色细节。系统提示完整保留后超过预算仍会明确拒绝发送。
- 全部工具、窗口和预留不变，长工具结果仍可能频繁触发必要压缩；摘要仍有损，需以原始记录核实事实。
- 模型仍可能重复读取；实测有大文件任务重复三次后被既有保护收束。相同工具、参数和结果的保护也可能中断用户有意重复的测试，阶段答复不代表全部请求均已完成。
- 阶段答复沿用单次无工具、关闭思考的既有策略；之后的新任务恢复正常工具和所选思考级别。固定的运行时状态标题不属于模型角色正文。
- 分词等待队列满、总等待超时或先前RPC未结束时仍会报错。SDK 1.5.0无法真正取消countTokens；连接一直不结束时需在空闲时重启插件。
- 仅验证当前文本、本机模型和匹配宿主组合；全新Windows安装及其他版本未全面验收。Low/Medium/High的效果依赖模型模板与加载映射，插件升级不自动修复模型元数据。
